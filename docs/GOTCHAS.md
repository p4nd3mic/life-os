# Gotchas / Non-Obvious Behaviors

**Snapshot analyzed:** `life-os-codebase-20260202`

This is the “things that will bite you at 2am” list.

---

## Serialization & naming

### snake_case vs camelCase (Rust ↔ TS)
- Rust Life Stream structs serialize with `camelCase` keys (`occurredAt`, `createdAt`, etc)
- Enums often serialize as `snake_case` strings (`awaiting_input`)

**When adding new fields**, update:
- Rust: `src-tauri/src/life_stream/types.rs`
- TS: `src/features/life-stream/types.ts`

…and verify you didn’t accidentally introduce a casing mismatch.

---

## Nested response wrappers (result.result)

The app-server + some tool layers can wrap payloads multiple times, e.g.:

- `{ result: {...} }`
- `{ result: { result: {...} } }`

Life Stream has to defensively unwrap these in:
- `src-tauri/src/life_stream/service.rs` (decision parsing + MCP parsing)

If you change upstream response formatting, expect breakage unless you update the unwrap logic.

---

## life-mcp runs from `/index.js` (no dist)

`LifeMcpBridge` will prefer a `dist/` build if present, but falls back to:
- `life-mcp/index.js`

**Implication:** in dev, you can run life-mcp without a build step.  
In prod packaging, ensure the expected entry exists in the bundle.

---

## `LIFE_OS_PATH` is critical

The Node MCP server relies on `LIFE_OS_PATH` to locate:
- the Obsidian vault root
- the `life-os` config root (systems YAML, categories)
- runtime paths (logs, indexes)

If `LIFE_OS_PATH` is missing/wrong, tools may still “run” but:
- persistence won’t work
- indexes won’t update
- lookups will appear empty

## Timezone handling: “Pacific” is implied, not enforced

Places where timezone matters:
- stream day keys / day headings
- “today” vs “yesterday” in daily stats
- dashboards grouped by date

In this snapshot:
- UI has helpers like `toPacificTime(...)`
- backend uses local time conversions (`chrono` local)

If the machine timezone isn’t Pacific, you can get subtle date-boundary bugs (cards in “wrong day”).

## Tool list mismatch: Node vs Rust

There are *two* high-frequency concepts:

- **Node**: `life-mcp/src/tool-registry.js` → `HIGH_FREQUENCY_TOOL_NAMES` (21 tools)
- **Rust**: `src-tauri/src/life_stream/mcp_registry.rs` → `high_frequency` (10 tools)

Also:
- Node has 16 categories in `CATEGORY_DEFINITIONS`
- Rust exposes only a minimal subset of categories/intents

**Impact:**
- A tool can exist in Node and even be registered in MCP… but Rust may never allow it.
- Rust’s decision prompt may not mention tools that are actually callable.

---

## Tool docs drift (MCP-TOOLS-REFERENCE.md)

`life-mcp/MCP-TOOLS-REFERENCE.md` is generated by `scripts/generate-tools-reference.js`.

In this snapshot, that generator:
- only includes a subset of tool groups
- can get out of sync with `src/tools/*.js` if not re-run

If you add tools, re-run the generator after installing deps.

---

## JSON Schema vs Zod schema split (life-mcp)

Most tools use “Zod param-map” inputs.

Some modules (notably `notes`, `inbox`, `knowledge`) use JSON Schema objects.

**Impact:**
- schema introspection (`get_tool_schema`) may be inconsistent
- keyword search / summaries may degrade if assumptions are Zod-specific
- best long-term fix: standardize on one schema system

## App is effectively hard-wired into Life OS mode (this snapshot)

`src/App.tsx` sets:

- `const lifeOsMode = true;`

So the UI always boots into Life Stream mode, even if the underlying workspace system supports other modes.

If you want “classic CodexMonitor mode”, you’ll need to reintroduce a toggle / route gate.

---

## Patch application pitfalls (front-end)

`streamStore.applyCardPatch(...)` uses truthy checks like:

```ts
if (patch.title) card.title = patch.title
```

This means you cannot patch a field to an empty string (`""`) — it will be ignored.

If you need that behavior, switch to explicit undefined checks:

```ts
if (patch.title !== undefined) ...
```

---

## HTML comment metadata is fragile (Obsidian stream files)

Life Stream embeds machine-readable metadata inside HTML comments:

- `<!--task:...-->`
- `<!--note:...-->`
- `<!--prompt_b64:...-->`

If you:
- reformat sections
- delete separator lines
- remove comments

…you can break reload/parsing.

---

## Files that must stay in sync

Common “double edit” points:
- Life Stream types
  - TS: `src/features/life-stream/types.ts`
  - Rust: `src-tauri/src/life_stream/types.rs`
- Tool allow-list / prompt list
  - Rust: `src-tauri/src/life_stream/mcp_registry.rs`
  - Node: `life-mcp/src/tool-registry.js`
- Obsidian schema expectations
  - Rust: `src-tauri/src/life_stream/obsidian.rs`
  - Vault: `_config/categories.yml`, entity templates
